## 2. Proposed minimal M2 implementation design

### Attempt entry and the pre-child baseline

Keep a selectable `opencode-agents` primary; a normal user message starts its conversational turn. Do not use `/m1` as the M2 request transport. At TUI plugin activation, synchronously call the existing `observeGit` for the plugin's local worktree and retain a clean snapshot in that generation. Register event listeners only after this snapshot exists. If it is dirty/unavailable, M2 cannot start in that generation. Accept only a **fresh Orchestrator root session first observed as `session.created` after that activation**, with one ordinary plain-text user input and no earlier conversation or queued input. This deliberately limits one M2 attempt to a new parent session. It gives the TUI a trusted clean root/HEAD observation before either model-originated child launch without relying on delivery timing of a later event. If the TUI is reloaded during a parent turn, that turn is ineligible; start a new session and attempt. Recheck the activation snapshot against Git when binding the parent and after both read-only children; do not refresh the bound HEAD.

The Orchestrator's instructions call one **foreground**, fresh native `planner`, then one **foreground**, fresh `implementer_slot`, and end its turn. Planner input must contain the exact parent user request using a small specified wrapper; `sessionID`, `background=true`, and a model override are disallowed for both calls. The slot input must be one fixed harmless bootstrap prompt (for example, `Reply READY only. Do not inspect or modify the repository.`) so its later transcript cannot contain a model-relayed proposal. The child must answer `READY`. Any failure to follow this contract ends this attempt. OpenCode agent choice, permission, transcript content, and native relationships remain execution facts only.

Listen for the fresh parent session's terminal execution event to *trigger* validation, then use `session.wait`, `session.get`, `session.inbox.list`, and paged `message.list` to validate the completed parent turn. Do not authorize from event payloads or a model-supplied ID. Require the parent to remain the expected primary in the bound location, have the one captured user input and a successful idle outcome, and contain exactly one completed native `subagent` Planner tool part and one completed native slot tool part for this turn, with no other subagent/tool route relevant to mutation. Keep each part's **parent assistant message ID + tool call ID + `metadata.sessionID`** as the invocation reference. Require distinct child IDs, no continuation `sessionID`, correct target names, completed foreground status, and no duplicate/extra calls. This whole-parent-turn check resolves parallel or late tool calls by failing closed. A second ordinary user turn in the parent is a new attempt requiring a fresh root session.

### Planner/result and slot binding

For the Planner call, fetch the ID named by that *completed parent tool part*, then require the child record's `parentID` to equal the captured parent, agent `planner`, same canonical location, no session permission override, successful idle outcome, and exactly one bootstrap user input matching the host prefix plus the recorded tool prompt. Require one successful final assistant response from `planner`, no synthetic/shell/extra user input, no unexpected role switch, and no pending inbox work. Compare the child final text to the exact foreground `output` represented by the parent tool result; reject missing metadata, malformed wrapper, differing text, `running` output, or a child/result from another call. Parse **that child final text** with unchanged `parseProposal`, then freeze with unchanged `makeCandidate(proposal, baseline.root, baseline.head)`. The parent answer may quote or summarize it but never supplies it to CAP. The Planner model may produce a bad proposal; that is a normal pre-authorization STOP.

For the slot call, bind its completed parent tool part the same way. Require `parentID`, role `implementer_slot`, matching location, no session permission override, a distinct fresh ID, one exact fixed bootstrap user input, final `READY` by the slot agent, matching parent tool result, no extra/synthetic/shell input, no pending inbox work, and idle success. Require the parent call arguments to omit `sessionID`, `model`, and background mode. The bootstrap role is mechanically read-only through ordered agent permissions: deny `*:*` first, then explicitly allow only read/search actions needed by that role; no shell, `execute`, edit, subagent, MCP/custom mutation or session-control action is allowed. The same conservative pattern applies to Planner and Orchestrator, except the Orchestrator's two exact subagent resources are allowed. Check the installed effective tool catalog and inherited session rules during implementation. If an unexpected nonempty session override exists, stop rather than trying to merge it away.

Keep these IDs and the frozen candidate in the active generation's one attempt closure, not in session metadata or storage. Before confirmation, re-read both parent call parts and both child records/transcripts; after confirmation and again before switch, recheck the slot's exact ID/parent, bootstrap prefix, expected role, successful idle state, zero extra input/pending work, and unchanged parent invocation reference. The Planner binding and candidate integrity are also rechecked. A model-supplied `sessionID`, another child with the same name/title, or a later slot continuation cannot substitute for the stored call-to-child identity. If any child was deleted, moved, switched, continued, or acquired unexpected input, stop. A slot continuation by the Orchestrator is allowed by host permission only under the slot role; it makes this governed attempt stale.

### Trusted admission and result

1. Read-only children are complete and bound. `requireFresh(observeGit(location, baseline), baseline)` and `candidateIntact` pass. Present `candidateMessage(candidate)` in the trusted `ui.dialog.confirm`, with the M1 fit check. Only `true` from that exact invocation proceeds.
2. After the await, check generation liveness, candidate integrity, bound parent/Planner/slot references, and Git freshness. Create `grantIntent(candidate, true, generation)` in private state. No child has edit capability yet.
3. Check liveness and idle/exact slot identity; call `session.switchAgent({sessionID: boundSlotID, agent: "authorized_implementer"})` once. After the await, check liveness, exact ID/parent/location, selected agent, no extra input or pending work, and fresh root/HEAD/cleanliness. Do not restore the slot during an active authorized turn.
4. Build the exact trusted implementation text from the unchanged M1 `implementerPrompt(candidate)` (rename its milestone wording for M2 if needed). Check liveness and consume the grant synchronously with `consumeIntent`. **The consumed bit is the admission boundary.** The following single `session.prompt({sessionID: boundSlotID, text: frozenText})` is the only trusted implementation dispatch. From the moment this call is issued, the host may have admitted the input even if the client gets an error, disconnect, or no reply. Never resubmit or create another Implementer for this candidate.
5. Check liveness after the prompt returns; require returned `sessionID`/input ID and payload to match the expected child and exact text, with no files/agents/skills. Retain its returned input ID. Await `session.wait` on that same ID. Read full child history and require the exact prefix (slot bootstrap user + slot final, role switch), followed by one trusted user input with the returned ID and byte-for-byte frozen text, no other input or role switch, one successful final assistant result under `authorized_implementer`, and no pending work. Require successful session outcome; reject an ambiguous result or changed agent. The implementation result is the bound native child turn, not the original parent bootstrap row or the Orchestrator's narration.
6. Reuse `observeGit(location, baseline)` and `requireInScope(result, baseline, candidate.proposal.files)` unchanged. This checks bound HEAD and every ordinary Git-observed changed path by exact equality. Report PASS/STOP through the TUI and stop before Reviewer, target construction, or Commit. Optional navigation to the exact child ID and a native toast are presentation only; they never alter the binding.

**State inventory.** All below are activation-private or local variables of one M2 attempt; none is persisted. The current `Generation.revoked` and `busy` flags, `IntentCandidate`, and `IntentGrant` already exist. Only the grant carries CAP authority. Native IDs, role selection, and tool capability do not.

| New state | Trusted owner; model influence | Established / invalidated | Why necessary; CAP authority |
| --- | --- | --- | --- |
| Activation Git baseline (`root`, `head`, clean paths) and eligibility of newly created Orchestrator IDs | Active TUI generation; Git observation and host-created IDs, not model claims | At activation, before accepting new parents; discarded on cleanup, mismatch, or attempted reuse | Establishes the normative pre-child baseline despite asynchronous native child launches; no grant |
| One selected parent session ID and its one user input ID/text | Attempt closure; user text is untrusted task input | From fresh-session and inbox/transcript evidence; invalid on extra input, move, role change, failure, or cleanup | Defines the current conversational attempt and exact request; no grant |
| Planner invocation reference (parent assistant message ID, tool call ID, child ID), Planner child input/final IDs and exact final text | Attempt closure; call arguments/output are model-influenced and independently checked against host records | From completed parent part and verified child history; invalid on mismatch or further input | Binds one native call, child, result, and frozen proposal; no grant |
| Slot invocation reference (same three IDs), bootstrap input/final IDs | Attempt closure; model chooses the call but cannot make the metadata authoritative alone | From completed parent part and verified read-only child; invalid on continuation, role/input/parent/idle change | Binds the exact later-admitted child; no grant |
| Exact implementation prompt text and returned prompt input ID | Attempt closure; trusted text derived from frozen candidate, host returns ID | Before consumption / after one prompt; invalid on ambiguity, error, or cleanup | Binds the admitted input and returned native result; no grant |

The existing candidate contains the validated proposal, root, HEAD, encoding, and digest; the existing grant contains purpose, digest, and consumed bit. No phase enum, retry count, continuation record, task registry, persisted child lifecycle, or cross-process capability is needed. An event listener's unsubscribe function and `busy` guard are ordinary plugin lifecycle resources. The selected parent and identities die with the attempt/generation; a reloaded generation does not reconstruct them from transcripts.

## 4. Implementation steps

1. Add the four native agent definitions with explicit ordered permissions. Inspect the installed effective tool catalog/agent rules, ensure the three pre-admission roles are read-only, the Orchestrator can name only Planner and slot, and the authorized role cannot self-admit through native routes. Reject nonempty session permission overrides in the binding path.
2. Add activation-time baseline capture and fresh-parent event eligibility to the existing TUI plugin. Register/unregister one listener in the active generation; keep `/m1` operational while sharing its `busy` guard. A dirty or unavailable baseline leaves M2 unavailable until a new clean activation.
3. Implement one M2 binder over paged parent and child messages. Establish the one-input parent turn, its two exact completed tool parts, source call IDs, distinct child IDs, exact Planner returned text, and fixed read-only slot bootstrap. Use events only to schedule this check. Fail on missing, multiple, stale, or unexpected records.
4. Reuse M1 proposal/candidate and Git helpers. Recheck initial baseline after both read-only children; construct and show the exact candidate with the trusted dialog and M1 fit logic.
5. Implement the confirmed exact-child rechecks, private grant, trusted role switch, post-switch liveness/identity/freshness checks, synchronous consumption, and **one** trusted prompt. Bind prompt ID/text and authorized child result; apply the unchanged Git scope gate. No redispatch path should exist in the function.
6. Add focused tests, typecheck, then review the final permission catalog and code path for one admission. M2 implementation completion remains separate from later live dogfood and M2 PASS.

## 6. Failure semantics

| Point of failure | Can implementation have begun? | Required action |
| --- | --- | --- |
| Initial baseline, parent/Planner/slot creation or binding, proposal parse, post-child freshness, or candidate display | No CAP implementation prompt; only read-only native turns may have run | STOP; discard bindings. A missing child/tool result is not repaired by picking a similar session. |
| Confirmation false/dismissed, or true followed by candidate/child/Git recheck failure before grant | No | STOP; the UI result is not rebound or retried. |
| Grant created, then generation revocation, stale state, or switch failure before consumption | No trusted implementation prompt. If switch succeeded, editing role may persist as ordinary OpenCode capability | STOP; discard unused grant. Do not prompt or infer authority from switched role. |
| Switch returned, post-switch check/freshness failure | No trusted implementation prompt, assuming the required idle/no-pending child check; direct trusted-local input remains outside this CAP path | STOP; leave any durable agent selection alone rather than attempting recovery. |
| Grant consumed just before calling `session.prompt`, with no call yet issued | No from this path; grant is spent | STOP. Never reuse the grant to try again. |
| Prompt call issued, returns an error, times out, disconnects, or yields uncertain ID | **Possibly yes**: host may already have admitted/woken the input | STOP, no second prompt/Implementer. Read-only inspection may explain state but cannot revive this attempt. |
| Prompt returned; wait, transcript/result binding, or Git observation/scope gate fails | Yes; edits and an authorized role can remain | STOP, no retry/repair/scope expansion, no Reviewer or Commit. Next attempt starts from current Git reality with new authority. |

The role switch is a preparatory capability change, not CAP consumption. The synchronous consumed bit is the one-use decision, and **issuing** the trusted prompt is the first point where implementation admission becomes host-ambiguous. `session.prompt` is not a completion operation. A late old-generation continuation checks `revoked` after every await and before any authority-bearing step. Cleanup marks `revoked` synchronously and unregisters listeners. An already admitted server turn may finish after reload, but no new generation imports its old grant, candidate, or worker identities.

## 7. Simplicity review

This design deliberately uses a few generation-local IDs and existing CAP/Git functions. It rejects a Workflow object, phase enum, persisted session bookkeeping, retry counters, continuation records, recovery tokens, general task registry, reusable capability service, server/MCP authority handoff, and upstream OpenCode change. It also rejects a model-provided child ID/digest, temporary permission unlock, generic permission `ask`, and a custom activity panel; native parent rows/family navigation already expose the child. The single new M2 module only validates native identities and coordinates one attempt.

The design was simplified during planning in two places. First, capture the clean baseline at TUI activation and accept a fresh one-turn parent, avoiding a timing-sensitive pre-Planner event gate or a persistent per-session baseline registry. Second, wait for the parent turn to finish and validate its complete tool parts/transcripts, avoiding a streaming correlation state machine. This deliberately fails closed when a model launches extra calls or a TUI generation misses the fresh parent. A later attempt uses a new parent and fresh authority. The plan is much smaller than `codex-agents`' Workflow MCP, durable artifacts, phases, and recovery machinery.

## 8. Open questions / blockers

**Ordinary implementation choices:** fix the exact Planner wrapper and harmless slot bootstrap literal; implement the strict parent tool-result text comparison against the current client's `Content` shape; decide whether a small informational toast is enough after PASS/STOP. These do not change CAP or Candidate 1. Confirm whether the installed `@opencode/plugin` `2.0.17` type surface includes the needed event, inbox, and switch APIs; align the dependency only if necessary. Determine the actual loaded tool names once the four role definitions exist, then make the allow/deny list complete. All of these are bounded implementation tasks with fail-closed defaults.

**Live dogfood questions:** normal navigation between Orchestrator and switched child, visible tool/reasoning rows when the provider emits them, dialog focus while the parent turn finishes, and cancellation/reload behavior during an admitted child turn require later explicit live verification. M1 dogfood did not prove these M2 interactions.

**Source-level architecture blockers:** none found in the inspected OpenCode `v2.0.18` APIs. Candidate 1 needs a native model-created read-only child, a trusted TUI role switch, and a trusted prompt to that exact existing child; current source exposes all three. The plan does not need TUI-created children, an atomic per-turn agent override, or a model-originated `authorized_implementer` call.
