## 2. Fixed constraints and narrow question

The project must run on unmodified stock OpenCode. No upstream API, fork, installed-package patch, host monkey patch/build, internal DB/event write, or fake model step may be required. Conversation is presentation, not CAP authority. Authorization remains a compact `session.composer.top` control with direct TUI-local Authorize/Cancel callbacks. Form/Question, commands, slash/keymap dispatch, and model prose cannot authorize. No Workflow, PlanStore, persisted attempt lifecycle/retry state, or cross-process CAP authority returns.

The narrow question is whether a supported custom-tool/lifecycle surface can show exact trusted Planner result `P`, or deterministic readable `F(P)`, in the existing root at zero clicks, without a model copy. If not, check for supported final-output replacement and minimize the composer-top fallback. Zero-click means the full plan can be inspected by normal scrolling in the current root; every line need not fit on one screen.

## 3. GenericTool visible input

An unknown custom tool name goes to `GenericTool` through fixed name dispatch ([display name set](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/message-parts.tsx), lines 21–40; [`ToolPart`](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 2392–2459). `GenericTool` initializes `expanded = false`. Before expansion it gives `InlineTool` only `genericToolSummary(tool, input)`; individual input fields and output are behind the expansion condition ([renderer](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 2551–2605).

[`primitiveInputSummary`](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/util/tool-display.ts), lines 13–20, includes every **top-level string, number, or boolean** field in insertion order as `[key=value, ...]`. Arrays, objects, null, and nested fields contribute nothing. `genericToolSummary` then replaces every whitespace run in that complete label with one space. Actual line breaks in `intent`, `plan`, or `files` strings become spaces, not visible lines. Literal backslash-`n` characters remain literal characters. Multiple primitive fields produce one logical label, such as `present_plan [intent=..., plan=..., files=...]`, not separate rows. Structured `{intent, plan, files: [...]}` hides `files` entirely until expansion; a single array/object containing the plan yields only the tool name. Nested structure cannot produce a readable multi-row plan.

The label is one text child of a compact [`InlineToolRow`](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/message-parts.tsx), lines 198–275. This generic call site has no explicit character cap, `truncate`, ellipsis, one-row height, or `wrapMode="word"`. Terminal layout may wrap screen cells, but source gives no stable width/line guarantee and cannot recover removed field boundaries. Expanded fields use `wrapMode="word"` and JSON stringify for non-strings: that is the click path. Tool `description`, schema, return `metadata`, or fields named `title`, `label`, `summary`, `preview`, or `status` do not change the generic summary or default expansion ([tool contract](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/schema/src/tool.ts), lines 14–19 and 67–102; generic renderer, lines 2551–2605). The AI SDK stream's optional tool-call `title` is not a GenericTool display field ([stream conversion](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/aisdk.ts), lines 781–825).

At medium verbosity a generic tool is a direct transcript row. Low verbosity groups non-text activity and can add a click; high does not change GenericTool logic ([grouping](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/grouping/session.ts), lines 30–32 and 78–91). The row persists from history; its expansion state is local. No primitive, array, or object input shape shows Intent, Plan, and Files as a complete, readable, trusted zero-click block.

**GENERIC TOOL INPUT HAS NO ACCEPTABLE ZERO-CLICK PLAN SHAPE**

## 4. Pre-recording trusted input injection

The precise local-tool order is:

```text
provider emits model-authored tool call X
→ host publishes durable Tool.Called(input: X)
→ updater stores X in the running assistant tool part
→ local execution fiber starts
→ Tool.snapshot.execute invokes tool.execute.before
→ runtime decodes/validates execution input and runs tool
→ Tool.Success/Failed supplies content/metadata, not replacement input
→ completed part retains X
```

The runner awaits publication before starting local execution ([step](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/step.ts), lines 100–129). The publisher records `asRecord(event.input)` ([publisher](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/publish-llm-event.ts), lines 458–475); the updater stores and retains it ([updater](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/message-updater.ts), lines 323–355). The TUI renders `part.state.input`, so the visible value is recorded **model-authored** X ([renderer](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 2395–2405). The supported `execute.before` hook can replace `event.input` for runtime dispatch, but it runs afterward ([installed declaration](../../node_modules/@opencode/plugin/dist/promise/tool.d.ts), lines 29–52; [dispatcher](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/tool.ts), lines 263–280). In-place mutation of a possibly aliased object is no documented durable update and has no corresponding projection event.

`context.tool.transform` edits tool definitions and executors, not a recorded invocation ([declaration](../../node_modules/@opencode/plugin/dist/promise/tool.d.ts), lines 13–28 and 53–60; [registry](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/tool.ts), lines 225–285). `session.context.tools` may edit the **model-visible definition** before dispatch; it cannot insert values after the provider emits its call ([request shaping](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/model-request.ts), lines 216–255). The schema is advertised as JSON Schema, but runtime decoding/default application occurs inside the executor **after** `Tool.Called` ([definition and decoder](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/tool/runtime.ts), lines 20–30 and 62–84). A schema default accepted at runtime therefore cannot make an omitted trusted field appear in canonical input. A required/constant field still relies on model-supplied bytes.

The public inventories have `tool.execute.before/after`, `session.prompt/context/generate`, outbound request/transport hooks, and AI SDK model hooks. There is no `tool.call.before`, pre-publication invocation hook, or host-level argument insertion point ([tool hooks](../../node_modules/@opencode/plugin/dist/promise/tool.d.ts), lines 29–60; [session hooks](../../node_modules/@opencode/plugin/dist/promise/session.d.ts), lines 13–47 and 129–145; [hook domains](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/plugin/hooks.ts), lines 13–19). Raw provider hooks are addressed in §6; they are not a canonical-input API.

**NO SUPPORTED PRE-RECORDING TRUSTED TOOL-INPUT INJECTION EXISTS**

## 5. Other public tool rendering surfaces

The public TUI API has coarse slots (`app`, footer, `session.composer.top`, `session.panel`, sidebar) and a Markdown **code-block** renderer. It has no tool renderer registration, per-tool component, inline output preview, transcript-row slot, progress renderer, or tool-name hook ([installed slot map](../../node_modules/@opencode/plugin/dist/tui/context.d.ts), lines 150–178 and 455–470; [TUI registry](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/plugin/api.tsx), lines 42–49 and 152–160). Fixed renderers for `shell`, `read`, `write`, `edit`, `patch`, `subagent`, `question`, and others are host-only name dispatch, not plugin registrations ([display set](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/message-parts.tsx), lines 21–40; [`ToolPart`](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 2416–2459). Registering a presentation tool under an action name would claim wrong semantics. The native Planner `subagent` row shows description/child ID and navigates to the child; it does not show the result in the root ([`Subagent`](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 3106–3137).

Code Mode is the one fixed renderer that can contain project-registered tools, but its `execute` row shows nested tool **input summaries**, not their results. Each nested call starts collapsed with `wrapMode="none"` and `truncate`; normal `execute` output is hidden unless opened in details, while an error preview is limited to four lines and represents failure ([`ExecuteCallView` and `Execute`](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 3163–3257; [Code Mode wrapper](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/codemode/tool.ts), lines 71–139). It cannot carry a successful exact plan zero-click, and nesting `present_plan` there adds code and a model-authored `execute` call rather than a new public renderer.

### Progress/status

A project tool can call `context.progress(update)` with metadata; the Promise declaration accepts `Record<string, any>` and the host publishes `session.tool.progress` containing JSON metadata ([declaration](../../node_modules/@opencode/plugin/dist/promise/tool.d.ts), lines 9–12; [publisher](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/publish-llm-event.ts), lines 561–570; [event schema](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/schema/src/session-event.ts), lines 522–530). The client applies it to the **running tool part's metadata** ([client reducer](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/client/src/solid/data.ts), lines 940–951). The event is ephemeral and has no durable projector. Success replaces the running state with terminal content and terminal metadata; persistence likewise projects only terminal success/failure ([client reducer](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/client/src/solid/data.ts), lines 953–979; [projector](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/projector.ts), lines 699–705; [updater](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/message-updater.ts), lines 340–374). Failure can snapshot last progress as metadata, but it is a failed tool, not a settled plan ([publisher](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/publish-llm-event.ts), lines 87–90 and 342–357).

Crucially, `GenericTool` receives `metadata` but never **reads** it. During execution and after completion it displays only its summary label, spinner/status icon, and expansion content ([`GenericTool`](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 2544–2601). Progress `{text: F(P)}`, `{status: F(P)}`, or any multiline value renders **zero plan characters** in its root row. Truncation, multiline support, natural scrolling, and visible binding of progress are moot because the text is not displayed. A plugin could read live metadata through the client only by adding its own slot outside the transcript. Holding the tool open would still show no plan and would prevent normal local-tool join and successful root-turn/idle, which current M2 requires ([step join](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/step.ts), lines 135–145; [M2 bind](https://github.com/mikechao/opencode-agents/blob/61550677ec5d6fec62549ef7c43fb028da74e7af/src/m2/attempt.ts), lines 92–99 and 212–240). It would worsen completion semantics.

**TOOL PROGRESS IS NOT A VIABLE ZERO-CLICK PRESENTATION SURFACE**

### Result content and metadata

Custom results permit optional encoded structured `output`, `content` as text or `{type: "text" | "file"}` items, and arbitrary JSON metadata ([tool schema](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/schema/src/tool.ts), lines 67–102). The runtime normalizes output to content and the runner publishes a nonempty terminal array ([runtime](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/tool/runtime.ts), lines 28–59; [publisher](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/publish-llm-event.ts), lines 573–590). For unknown tools, `ToolPart` flattens text items to text and file items to name/URI; `GenericTool` displays that entire string **only after expansion** ([renderer](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 2395–2406 and 2551–2597). Markdown/code fences remain plain expanded text. Structured output does not select another renderer; metadata supplies no generic label or preview. An image file item can enter an optional thumbnail path, but it is not exact readable plan text ([image path](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/index.tsx), lines 2464–2541). Diff and diagnostics blocks belong to built-in edit/patch renderers and would falsely imply edits. Notices, task objects, annotations, and arbitrary structured blocks are not custom result variants.

`present_plan({}) → F(P)` remains an exact, persistent, bindable root tool result, collapsed by default. It scrolls naturally **after expansion**, so it fails zero-click.

**NO SUPPORTED CUSTOM TOOL RESULT TYPE PROVIDES ZERO-CLICK PLAN DISPLAY**

## 6. Trusted final-output replacement

Root assistant `TextPart` is immediately rendered as Markdown in normal transcript flow ([text renderer](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/tui/src/routes/session/message-parts.tsx), lines 169–195). A model-authored final can be compared byte-for-byte to `F(P)`, but requires a potentially long exact copy; any difference must STOP. The [M2 trailing-space failure](milestone-2-live-dogfood.md) illustrates this availability class, although that copy was root-to-Planner prompt, not final text.

There is **no session/message hook replacing a primary assistant final text part** before `session.text.started/ended` persistence. `session.context/generate` edit outbound request inputs/options/tool definitions; `session.title.result` and `session.compaction.result` short-circuit auxiliary products, not a root final ([session declarations](../../node_modules/@opencode/plugin/dist/promise/session.d.ts), lines 21–50 and 129–145; [request dispatch](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/model-request.ts), lines 206–255 and 378–386). Normal assistant text projects from provider text events ([publisher](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/publish-llm-event.ts), lines 400–420; [updater](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/message-updater.ts), lines 288–300). Tool results enter later model context, not an automatic text substitution ([lowering](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/runner/to-llm-message.ts), lines 301–302). No host template/reference expansion, citation syntax, final postprocessor, or message replacement route was found in the public declarations and dispatch.

Broader public hooks deserve explicit treatment. `session.http.response` can replace a raw HTTP `Response`, and experimental WebSocket receive can replace a raw frame before provider parsing ([declarations](../../node_modules/@opencode/plugin/dist/promise/session.d.ts), lines 65–114; [dispatch](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/session/model-request.ts), lines 295–347). Producing `F(P)` there would require provider-specific stream protocol rewriting, including finish/tool messages. These are transport hooks, not a model-independent final-presentation operation.

The overlooked `aisdk.language` hook is public and can supply a complete `LanguageModelV3` adapter. A wrapper's `doStream` can theoretically buffer and substitute text events before OpenCode projects them ([installed declaration](../../node_modules/@opencode/plugin/dist/promise/aisdk.d.ts); [host adapter](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/plugin/host.ts), lines 157–186; [stream conversion](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/aisdk.ts), lines 708–768). **This is whole model-adapter replacement, not a supported final-output replacement hook.** It is initialized/cached per model, not per root session or final message; the hook event has model/options, not target session/message ID or P ([AI SDK initialization](https://github.com/anomalyco/opencode/blob/cd9a14a6b688d4021bee381dfd39d2cef9c0f862/packages/core/src/aisdk.ts), lines 304–349). It runs only when `Provider.isAISDK(model.package)`; other stock transports bypass it (same source, lines 318–322). Selecting a particular root final would require side-channel request tagging or parsing model prompt/tool history. Rewriting streams must preserve tool calls, finish reasons, errors, usage, cancellation, and fragment identities. It would attribute substituted bytes to the model in normal assistant history. That is a custom model-stream/protocol implementation with fake output attribution, outside the narrow supported presentation seam and settled no-fake-model-step constraint. A custom provider implementation has the same problem.

Thus ordinary assistant-final presentation still relies on exact model copying and strict comparison. Correct copies can be accepted conditionally, but are too fragile as the preferred UX.

**VERIFIED ROOT FINAL REMAINS TOO FRAGILE**

## 7. Binder / authority implications

No newly examined tool surface passes zero-click. Current M2's exact root, Planner and slot histories; message/tool/child IDs; P wrapper comparison; successful idle; candidate construction; generation liveness; root/location/HEAD/worktree freshness; and one-use grant remain the authority path ([M2 binder/admission](https://github.com/mikechao/opencode-agents/blob/61550677ec5d6fec62549ef7c43fb028da74e7af/src/m2/attempt.ts), lines 92–184 and 212–263; [candidate formatter](https://github.com/mikechao/opencode-agents/blob/61550677ec5d6fec62549ef7c43fb028da74e7af/src/m1/proposal.ts), lines 52–101). Conversation and tool metadata remain non-authoritative.

If a future supported tool row could show trusted text, an active strip would bind root session ID, assistant message ID, tool-call ID, exact **visible** input/progress/result bytes, exact Planner child final P, deterministic `F(P)`, and entire parent history, rechecked before grant. For supported trusted final-output replacement it would bind exact final assistant message ID/content, P/`F(P)`, and entire parent history. Missing, changed, ambiguous, or truncated visible content means STOP. Invisible progress or execution-time-only input cannot satisfy that binding.

For composer-top, parent history can remain `H0`. The trusted TUI directly renders `candidateMessage(C)` from frozen C; candidate digest/HEAD and callback closure stay activation-private. The component must be mounted in the bound root and readable before Authorize activates. Navigation, unmount, unreadable resize, generation loss, candidate change, or history/freshness mismatch means STOP. There is no transcript mutation or persisted CAP state.

## 9. Recommended stock-OpenCode direction

Use the **trusted full-plan `session.composer.top` fallback** with direct TUI-local Authorize/Cancel. Stock OpenCode exposes no acceptable zero-click custom-tool input, progress, or result surface, and no supported final-message replacement. Keep the root conversation for ordinary context and child navigation; it is neither presentation proof nor authorization source. Preserve the M2 binder and fail-closed checks. The collapsed `present_plan` output and model-final exact copy are not the selected reading flow.

## 10. Composer-top fallback presentation principle

The fallback can feel closer to the selected hybrid prototype even though mounted above the composer: render exact full Intent, Plan, and Files as quiet transcript-aligned text using most available width, little or no border, one bounded scroll region, and a compact sticky Authorize/Cancel row. Put HEAD/digest/worktree identity in a restrained adjacent line while keeping complete candidate text and implementation-only scope inspectable. Avoid a duplicate large title, padded frame, or stacked workflow-card chrome. Cap height so normal conversation/composer stay visually primary; let the plan scroll within its region. Controls remain fixed, and Authorize disables if the region cannot expose every line by scrolling. This is a public-slot presentation principle, not an implementation design or relaxed binding.

## 11. Required proof before implementation planning

**One bounded user-run probe remains.** Source proves the slot mount and local callback API, but cannot establish legibility, scrolling, pointer/focus behavior, JSX peer loading, and resize behavior of this minimal component in the installed 2.0.18 TUI. In a disposable `/tmp` project, the user runs stock OpenCode with an inert multiline sample in `session.composer.top` and local buttons that only log disposable Authorize/Cancel events. At normal and narrow supported sizes, verify every line can be reached by scrolling while controls remain visible; direct pointer/focus activation reaches only the local callback; root-to-child navigation, reload, and unreadable resize remove/disable affirmative action. Do not create a real CAP attempt, run an Implementer, or touch this repository. No separate tool-input, progress, result-type, or final-output probe is needed for their source-established limits.
